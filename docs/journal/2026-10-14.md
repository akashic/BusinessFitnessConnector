Reading `paconn`'s source showed it always applies Microsoft's certification rules, so the endpoint was called directly with those rules on and off. With them off, the definition passed. Planting known mistakes then showed:
  - the validator reports in stages;
  - the certification-off check is lenient.

  Probing past the first stage showed the real definition passes the full certification rule set apart from 25 path warnings. An earlier "9 warnings" figure was corrected to 25, and two scripting slips that briefly reported false passes were caught by cross-checking.

The file is looked for next to the collection rather than in the current folder, so the tests don't pick up the repo's real file. No response schemas were invented for the Documents API.
- **CI.** It tests Python 3.10 and 3.14 (locally the suite passes on 3.9, 3.11 and 3.14), with action versions looked up rather than guessed. Giles's GitHub token already had the `workflow` scope.
- **Generic guide.** Following Giles's mid-task request, the `paconn` guide was written for any connector project. It folds in what's useful from all the lessons, and every point is marked as either tested or taken from the docs. Unverified statements were removed or relabelled before committing: a retry-policy claim, a trailing-punctuation claim, a misattributed source, and an understatement of Microsoft's position on client-credentials sign-in.
